# GStack Multi-Agent Virtual Engineering Company Playbook

Adapted and expanded from [garrytan/gstack](https://github.com/garrytan/gstack) for universal cross-model execution across Claude Code, Cursor, OpenAI Codex, Gemini CLI, OpenCode, Windsurf, and Antigravity.

## 1. The Sprint Pipeline (`Think -> Plan -> Build -> Review -> Test -> Security Audit -> Ship -> Reflect`)

Every complex feature or project runs through specialist personas that feed artifacts into `.ai-memory/`:

| Command / Mode | Specialist Persona (30-50 YOE) | Core Responsibility & Output |
| :--- | :--- | :--- |
| `/office-hours` | YC Partner & Product Strategist | Asks 6 forcing questions to challenge assumptions, extracts hidden capabilities, and writes the product design brief into `.ai-memory/DECISIONS.md`. |
| `/plan-ceo-review` | Founder / CEO | Finds the "10-star product" inside the request. Selects one scope mode: `EXPANSION`, `SELECTIVE_EXPANSION`, `HOLD_SCOPE`, or `REDUCTION`. |
| `/plan-eng-review` | Principal Engineering Manager | Locks system architecture, ASCII data-flow diagrams, state machines, error-handling matrices, and concurrency boundaries. |
| `/plan-design-review` | Principal Product Designer | Grades UI/UX dimensions 0-10 (typography, hierarchy, contrast, spacing, responsive reflow), detects and removes "AI slop", and writes `DESIGN.md`. |
| `/plan-devex-review` | Developer Experience (DX) Lead | Audits Time-To-Hello-World (TTHW), CLI/API ergonomics, and agent-readable structured error messages. |
| `/spec` | Principal Staff Architect | Converts intent into a 5-phase executable specification (`Why -> Scope -> Technical Code-Read -> Draft -> Verification Gate`). |
| `/design-shotgun` & `/design-html` | Design Engineer | Generates 4-6 distinct visual layout directions and compiles the chosen design into production-ready, responsive HTML/React/Vue/Svelte with zero placeholder slop. |
| `/review` | Staff Bug-Hunter Engineer | Hunts for bugs that pass CI but break in production: race conditions, stale state, N+1 queries, memory leaks, unhandled rejections, and weakened tests. |
| `/verify` | Build & Gate Verification Loop | Runs `typecheck`, `lint`, `build`, and targeted tests iteratively until 100% green. Never marks a change complete without test coverage. |
| `/qa` & `/browse` | QA Automation Lead | Opens a real browser (via Playwright MCP or GStack browser), clicks through flows, inspects console/network errors, writes regression tests, and verifies fixes. |
| `/cso` & `/redteam-audit` | Chief Security Officer (CSO) | Runs OWASP Top 10 + STRIDE threat modeling, static/dynamic security scanning, and authorized local stress/load tests (`k6`, `autocannon`, `locust`). |
| `/ship` & `/canary` | Release Engineer & SRE | Syncs branch, audits documentation via `/document-release`, opens PR with evidence cards, and monitors post-deploy console/performance metrics. |
| `/captain` | Multi-Agent Crew Controller | Coordinates parallel subagents working in isolated git worktrees or modules, verifying each lane's `READY` block before merging. |
| `/careful`, `/freeze`, `/guard` | Production Safety Warden | Blocks destructive shell/database commands (`rm -rf`, `DROP TABLE`, force-push) and locks edits to the active target directory during debugging. |

## 2. Six Forcing Questions for `/office-hours` & Prompt Expansion

Whenever a user submits a high-level idea, evaluate these 6 questions internally (and ask the user only when a critical product direction is genuinely ambiguous):

1. **Pain vs. Feature**: What is the exact painful workflow happening right now before this tool exists?
2. **The Narrowest Wedge**: What is the smallest version of this product that delivers undeniable value today?
3. **Hidden Capabilities**: What 3-5 underlying capabilities did the user implicitly describe without naming them?
4. **Failure Premortem**: If this breaks in production at 10,000 concurrent users, what failed first?
5. **Anti-Slop Differentiator**: What makes this feel crafted by a world-class team rather than generated by a default template?
6. **Verification Proof**: How will we prove with automated tests and browser/3D visual checks that it actually works?
